# 可视化控制台

打开 /admin，输入服务端 ADMIN_TOKEN 后连接。令牌只保留于本页面内存，刷新后重新输入。

## 部门卡片

- 应到人数支持数字输入和加减按钮。修改后点击本卡片的“保存设置”才生效。
- 留空：按 CSV 中该部门 required=1 的名单逐人匹配，所有应到人员签到才自动完成。未匹配签到不计入名单完成进度。
- 填写数字：以本部门签到总数达到该人数自动完成，不再逐人核验名单。
- 0：不自动完成；可手动标记完成。没有人数或名单也不会自行完成。
- 自动判定、手动标记已完成、手动保持未完成三种状态可选。手动状态优先于自动判定，直到切回自动。
- 手动标记完成不增加签到记录，不隐藏未到人员，也不关闭手机签到入口。
- 状态和人数立即同步大屏，重启服务后保留。大屏会区分人工标记完成与自动完成。

## 修改签到记录

可按姓名搜索、按部门筛选。点击“修改”打开弹窗，可改姓名、部门、颜色；保存保留原记录ID和签到时间，重新匹配名单，更新新旧部门人数。

同部门同名记录会阻止保存，不能借编辑覆盖另一人的签到。请求失败时保留输入。撤销需要二次确认，并立即同步大屏。服务端记录修改前后的姓名、部门、颜色供审计。

## CSV 导入

保留 name,department,required 格式。下载模板 → 选择文件 → 预览并校验 → 确认替换应到名单。中文部门名和固定英文ID均支持。required 必须为1或0。

文件需UTF-8编码，支持BOM、引号和逗号转义。空名单、重复姓名+部门及无效行会拒绝整次导入，不会静默忽略。导入替换名单并重新关联已有签到，不删除签到记录，也不重置手动人数或完成模式。需要重新按名单判定时，点击“按名单人数”，选择自动判定，再保存。

## 验证范围

node --test tests/colors.test.cjs：鉴权、非法人数、三种模式、0值、编辑冲突、跨部门编辑、原时间保留、已有签到时重复导入名单、非法名单拒绝、恢复名单人数、重启持久化，以及原有颜色/SSE测试。

控制台未提供批量清空签到按钮。后台原有的姓名+部门身份模型不适合同部门同名人员，正式名单存在此情况时需要进一步引入稳定人员ID。
